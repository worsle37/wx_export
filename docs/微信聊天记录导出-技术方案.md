# 微信 PC 端聊天记录导出 — 技术方案（可复用管线）

> 目标环境：Windows + 微信 4.x（本机实测 `Weixin.exe 4.1.15.13`，数据目录 `C:\wechat_data\xwechat_files`）
> 本文件记录已实测的每一步、判定条件与代码形态，可直接据此写成程序。

---

## 0. 总览

```
① 定位数据目录 → ② 以共享读方式访问被独占占用的 db → ③ 判定加密形态
      → ④ 取密钥（按微信版本分岔）→ ⑤ 页级解密成明文 SQLite
      → ⑥ 解析 schema：会话名→username→Msg_<md5(username)> 表
      → ⑦ 按目标联系/群导出（HTML/CSV/Markdown）
```

关键结论先行：

| 项目 | 实测值 |
|---|---|
| 加密算法 | SQLCipher 4（WCDB 封装）AES-256-CBC |
| 认证 | HMAC-SHA512 |
| KDF | PBKDF2-HMAC-SHA512，**256000** 次 |
| 页大小 | 4096 |
| 保留区 | 80 字节 = IV(16) @4016 + HMAC(64) @4032 |
| 密钥粒度 | 每个 `.db` 独立 salt（文件头 16 字节），但共享同一个 **account-level passphrase** |
| 本机版本 | 4.1.15.13 → **零驻留（≥4.1.10）**，被动内存扫描不可行 |

## 1. 定位数据目录

配置在 `%APPDATA%\Tencent\xwechat\config\*.ini`（内容就是数据根目录，本机为 `C:\wechat_data`），
数据在 `<根>\xwechat_files\<wxid>_<hash>\db_storage\`。

```powershell
Get-Content "$env:APPDATA\Tencent\xwechat\config\*.ini"
Get-ChildItem "C:\wechat_data\xwechat_files" -Directory        # 每个账号一个目录
```

数据库清单（本机实测大小）：

```
db_storage\message\message_0.db        100 MB   ← 最新消息分片（主要目标）
db_storage\message\message_1.db         27 MB   ← 历史分片
db_storage\message\message_2.db        0.5 MB
db_storage\message\message_fts.db       28 MB   ← 全文索引
db_storage\message\media_0.db          8.5 MB
db_storage\message\biz_message_0.db     28 MB   ← 公众号
db_storage\contact\contact.db          6.4 MB   ← 联系人 / 群（名称→username 映射）
db_storage\session\session.db          0.5 MB   ← 会话列表
db_storage\sns\sns.db                  8.0 MB   ← 朋友圈
```

## 2. 读取被微信独占锁定的 db

微信以「不共享读」方式打开 db，`File.OpenRead` 会报“正由另一进程使用”。
实测可用组合：`FileAccess.Read + FileShare.ReadWrite`；`cmd copy` 也能成功。

```powershell
$fs = [System.IO.File]::Open($path,'Open','Read','[System.IO.FileShare]::ReadWrite')
# 或：cmd /c "copy /y db copy.db"
```

Python 侧直接用 `open(path,'rb',buffering=0)` 即可（默认共享读写）。

## 3. 判定是否已加密

读前 16 字节：`53 51 4c 69 74 65 20 66 6f 72 6d 61 74 20 33 00`（"SQLite format 3\0"）= 明文；
否则随机字节 = SQLCipher，前 16 字节就是该库的 **salt**。

## 4. 取密钥（按版本分岔，这是唯一的硬门槛）

### 4.1 版本判定

```powershell
(Get-Item 'C:\Program Files\Tencent\Weixin\Weixin.exe').VersionInfo.ProductVersion
```

| 版本段 | 内存中的密钥形态 | 可行手段 |
|---|---|---|
| 4.0.x ~ 4.1.9 | `x'<64hex enc_key><32hex salt>'` 字符串，或 32 字节 passphrase 半驻留 | 被动内存扫描 |
| **≥ 4.1.10** | **零驻留**：派生后即丢弃，稳态内存无任何形态 | ① 断点/Hook 抓取 ② 降级到 4.1.9 提取 ③ Config.Cipher 对象扫描（部分版本有效） |

本机 4.1.15.13 已实测：
- 1.8 GB 内存转储里 `x'[0-9a-f]{96}'` 命中 **0**
- 以 enc_key 为目标的 32 字节暴力枚举（AES-NI，1.8 GB / 4 字节步长）命中 **0** ——因为内存里根本不存在 enc_key，只有 PBKDF2 之前的 passphrase

### 4.2 原语：判定一个候选 enc_key 是否正确（通用）

```python
from Crypto.Cipher import AES
TARGET = b"SQLite format 3\x00"
iv = page1[4016:4032]                       # reserve=80 → IV 在 4016
C1 = page1[16:32]
if AES.new(enc_key, AES.MODE_ECB).decrypt(C1) == bytes(a^b for a,b in zip(TARGET, iv)):
    print("enc_key 正确")
```
即 AES_dec(K, C1) == 明文头 XOR IV，128 位精确判据，假阳性 2^-128。

### 4.3 原语：判定一个候选 passphrase 是否正确

```python
from hashlib import pbkdf2_hmac
enc_key = pbkdf2_hmac("sha512", passphrase, page1[:16], 256000, 32)   # 每候选约 0.16 s
# 再套用 4.2 判定
```

### 4.4 路线 A：被动内存扫描（仅 ≤4.1.9）

1. `OpenProcess(PROCESS_VM_READ|PROCESS_QUERY_INFORMATION)` 打开所有 `Weixin.exe`
2. 用 `VirtualQueryEx` 遍历 `MEM_COMMIT` 且可读、排除 `PAGE_NOACCESS` 的区域（本机 1.8 GB / 5 进程）
3. `ReadProcessMemory` 转储后在本机离线搜 `x'(96hex)'`；命中后前 64 hex = enc_key，后 32 = salt
4. 用 4.2 判定

> 本机 `findkey.py / dump_mem.py / scan_key.c` 即该路线的实现（含自研 AES-NI 枚举器，
> 1184 MB / 4 字节步长 / 单线程 14 秒）。

### 4.5 路线 B：Hook 抓 passphrase（≥4.1.10 的通用解）

- x64dbg / Frida spawn 注入 `Weixin.exe`，在 `Weixin.dll` 的 WCDB codec 配置函数下断
- 定位线索：字符串 `com.Tencent.WCDB.Config.Cipher` / `MMV1` 的交叉引用；每次小版本 RVA 都会变
- 4.1.12.x：`RCX` 指向的结构体前 32 字节 = passphrase；4.1.1.x：`RDX+8`
- 必须 **spawn**（启动时注入）或登录瞬间抓，attach 稳态进程抓不到
- 有注入检测/封号风险，主号慎用

### 4.6 路线 C：降级提取（最稳，无注入）

1. 备份 `C:\wechat_data\xwechat_files`
2. 装微信 ≤4.1.9（同机或虚拟机），登录同一账号
3. 走 4.4 提到 passphrase / enc_key
4. passphrase 与账号绑定、跨版本有效 → 回到 4.1.15 照常解密
5. 提取后屏蔽自动更新（hosts 拦 `dldir1.qq.com` / `dldir1v6.qq.com`）

### 4.7 路线 D：Config.Cipher 对象扫描（无注入，需管理员）

在内存中找 `com.Tencent.WCDB.Config.Cipher` 字符串，枚举其附近 ±0x800~0x2000 的 32 字节窗口当
passphrase 候选，逐个 PBKDF2 验证（每候选 0.16 s，多进程并行）。
`scan_pass.py` 即此实现；部分版本 Config 对象里 passphrase 已被抹掉，命中率不确定。

## 5. 页级解密（拿到 enc_key 之后）

```python
PAGE, IV_OFF = 4096, 4016
def decrypt_db(enc_key, src, dst):
    data = open(src,'rb').read()
    salt = data[:16]
    out = bytearray()
    for pgno in range(1, len(data)//PAGE + 1):
        page = data[(pgno-1)*PAGE: pgno*PAGE]
        iv = page[IV_OFF:IV_OFF+16]
        body = page[16:IV_OFF] if pgno == 1 else page[:IV_OFF]
        pt = AES.new(enc_key, AES.MODE_CBC, iv).decrypt(body)
        if pgno == 1:
            pt = b"SQLite format 3\x00" + pt
        out += pt + b"\x00" * (PAGE - len(pt))
    open(dst,'wb').write(out)
```

注意：
- `-wal` 里的新消息需同样处理（WAL 帧解密）或用「微信退出后再复制」的干净快照
- 媒体（图片/语音/视频）是**另一套** XOR/AES 密钥，与 db 密钥不同

## 6. 解析 schema

每个会话一张表：`Msg_<md5(username)>`（username 为 `wxid_xxx` 或 `xxx@chatroom`）。

```sql
CREATE TABLE Msg_xxxx (
  local_id INTEGER PRIMARY KEY, server_id INTEGER, local_type INTEGER,
  sort_seq INTEGER, real_sender_id INTEGER, create_time INTEGER,
  status INTEGER, upload_status INTEGER, download_status INTEGER,
  server_seq INTEGER, origin_source INTEGER, source TEXT,
  message_content BLOB, compress_content BLOB, packed_info_data BLOB,
  WCDB_CT_message_content INTEGER,   -- 0=明文, 4=zstd
  WCDB_CT_source INTEGER);
CREATE TABLE Name2Id (user_name TEXT, is_group INTEGER);  -- rowid ↔ real_sender_id
```

- `local_type & 0xFFFF`：1 文本 / 3 图片 / 34 语音 / 43 视频 / 47 表情 / 49 富媒体 / 10000 系统
- `WCDB_CT_message_content == 4` → `zstd.decompress()` 后再 UTF-8 解码
- 群聊文本形如 `wxid_xxxx:\n正文`
- `message_1/2.db` 的 `real_sender_id` 有时是会话内角色号而非全局 rowid，需用锚点句校验

## 7. 名称 → username（群名/昵称能不能对上 id）

**能，不需要逆向。** 名称就是数据库里的普通字段：

- `contact.db` → `contact` 表：`username`（wxid/xxx@chatroom）、`nick_name`、`remark`（备注）
- 群聊：`username` 以 `@chatroom` 结尾，`nick_name` 就是群名
- 先用「备注优先，其次昵称」精确匹配；同名/多结果时把候选列表（含成员数、最近消息时间）抛给人选

匹配到 username 后：`table = "Msg_" + md5(username).hexdigest()`。

## 8. 导出

- 单聊/群聊一样处理，群聊按 `real_sender_id` → `Name2Id` 还原发言人
- 输出 HTML（带时间轴、发言人、图片/文件占位链接）+ CSV（便于二次处理）
- 媒体路径：`msg\attach\<md5>`、`msg\file`、`msg\video`（需另解媒体密钥）

## 11. 本机实测结论（2026-10-27，微信 4.1.15.13）

| 尝试 | 结果 |
|---|---|
| 读被锁 db（`FileShare.ReadWrite` / `cmd copy`） | ✅ 成功，可拷贝 100 MB 的 message_0.db |
| 判加密 | ✅ SQLCipher，salt 各有不同（message_0=`xxxx…xxxx`，session=`xxxx…xxxx`，contact=`xxxx…xxxx`） |
| 内存搜 `x'<96hex>'`（1.8 GB / 5 进程） | ❌ 0 命中 |
| AES-NI 暴力枚举 enc_key（1.8 GB，4 字节步长，14 s/1.2 GB） | ❌ 0 命中 → enc_key 不驻留 |
| `Config.Cipher` 字符串邻域枚举 passphrase（2387 候选） | ❌ 0 命中，附近也没有 256000/4096 常量 → 配置对象已被抹 |
| Frida spawn hook（`MMV1` / `Config.Cipher` xref 所在函数，抓到 437 个内存窗口 / 7254 候选） | ❌ 0 命中 |
| UIA 读取主界面消息文本 | ❌ 主窗口只暴露 2 层 Pane，消息区为自绘、无 UIA 文本（登录页的 mmui 控件反而能读） |

**因此在本机版本上，唯一还没试的两条确定路径是：**

1. **降级提取（推荐）**：装微信 ≤4.1.9 → 登录同账号 → 4.4 的内存扫描拿 passphrase → 回到 4.1.15 用同一 passphrase 解密。passphrase 与账号绑定、跨版本有效。
2. **精确 hook**：在 `Weixin.dll` 里定位 SQLCipher 的 `set_pass` / codec 初始化函数（已知线索：`kdf_iter`/`cipher_page_size` 的 xref 指向 RVA `0x5839400`；`com.Tencent.WCDB.Config.Cipher` 指向 `0x14824D0`，但后者运行期未触发），在 db 打开瞬间读入参。

> 副产物：这台机器上登录页需要点「进入微信」，用 `post_click.ps1` 发窗口消息可稳定自动化（`SetForegroundWindow` 被前台锁挡住时也可用）。

## 12. 最终解决方案（实测成功，2026-10-27）

**结论：微信 4.1.11+ 的密钥不是以明文 `x'<hex>'` 存在，而是以 XOR 掩码后的 blob 存在
`com.Tencent.WCDB.Config.Cipher` 配置对象里。** 这就是所有「直接内存搜 hex」工具失效、
而 `wcdb-key-tool` 能成功的原因。

### 12.1 对象结构（Windows，实测 4.1.15.13）

```
1) 找到字符串 "com.Tencent.WCDB.Config.Cipher" 的地址 S
2) 搜 QString/ref 对：pack('<Q', S) + pack('<Q', 28) → 命中地址 Q
   node = read(Q - 0x10, 0x50)
   config_ptr = u64(node + 0x28)
3) obj = read(config_ptr + 0x88, 0x28)
   data_ptr = u64(obj + 0x8); data_len = u64(obj + 0x10)   # 实测 99 字节
4) blob = read(data_ptr, data_len)
   decoded = blob XOR MASK（循环）
5) 在 decoded 里正则找 x'<64hex enc_key><32hex salt>' → HMAC 校验 page1
```

XOR 掩码（固定字节串）：

```
d2 c7 44 24 58 02 00 00 00 48 89 44 24 50 48 8b
45 00 48 84 4c 24 48 48 89 44 25 40 48 58 4c 24
```

### 12.2 判定（HMAC 校验，务必做，否则可能抓到错值）

```python
mac_salt = salt XOR 0x3a
mac_key  = PBKDF2-HMAC-SHA512(enc_key, mac_salt, 2, 32)
valid    = HMAC-SHA512(mac_key, page1[16:4032] + pack("<I", 1)) == page1[4032:4096]
```

### 12.3 一次性可复用的工具链

```powershell
# 1) 取密钥（只读扫内存，不注入、不改微信）
python tools\wcdb_key_tool_windows.py extract --db-dir "<账号目录>\db_storage" --output all_keys.json
# 2) 解密全部 db（AES 走系统 bcrypt.dll，无需第三方库）
python tools\wcdb_key_tool_windows.py decrypt --db-dir "<账号目录>\db_storage" --keys all_keys.json --output decrypted
# 3) 按会话导出（本仓库脚本）
python export_messages.py
```

实测结果：36 个库解密成功（含 message_0/1/2、contact、session、sns），
`message_0.db` 100.7 MB / 25779 页，HMAC 全部通过。

### 12.4 会话定位与导出

```
nick_name/remark → contact.username → "Msg_" + md5(username) → message_0.db 里的表
```
示例（占位值）：
- 单聊 `示例会话C` → `wxid_demo0002` → `Msg_<md5(username)>`
- 群聊 `示例会话B` → `10000000000@chatroom` → `Msg_<md5(username)>`

发送者：`real_sender_id` → `Name2Id.rowid` → username → 备注/昵称；群聊文本自带
`wxid_xxx:\n` 前缀，可直接取发言人。

导出产物：`out\示例会话C.md|.csv|.html`（文件名 = 会话名净化后 + 扩展名）。

### 12.5 注意

- `all_keys.json` 里是每个库的 enc_key，等同于钥匙，别外传
- 每个库 salt 固定在文件头，密钥长期有效；换账号/重装需重新提取
- 媒体（图片/语音/视频）是另一套 AES key，本次未解
